# Приложение Д

# Листинги ключевых файлов

## Назначение приложения

Приложение Д предназначено для размещения выбранных фрагментов исходного кода, подтверждающих реализацию ключевых частей Kiosk_v001. В итоговую версию курсовой работы не следует переносить весь проект целиком: достаточно включить компактные листинги, которые напрямую связаны с архитектурой, хранением данных, административными сценариями, публичным API, обработкой изображений, клиентской логикой экранов и регрессионными проверками.

В приложении не должны размещаться секреты, содержимое базы данных, загруженные пользовательские файлы, generated-файлы, build/dist-артефакты и runtime-данные. Каждый листинг должен иметь понятную подпись и использоваться как доказательство конкретного проектного решения, описанного в главе 3.

## Рекомендации по включению листингов в DOCX

Листинги в итоговом DOCX должны быть короткими и привязанными к конкретным разделам главы 3. Не следует дублировать код, который уже объяснен текстом, или включать однотипные CRUD-маршруты целиком. Если фрагмент получается слишком длинным, его лучше сократить до наиболее показательных функций и добавить пояснение перед листингом.

В финальном документе рекомендуется использовать моноширинный шрифт, единую нумерацию листингов и подписи вида «Листинг Д.1 — ...». Если требования оформления позволяют, из листингов можно удалить нерелевантные imports и вспомогательные строки, не влияющие на понимание алгоритма. При этом нельзя изменять смысл кода: сокращение должно быть явно редакционным.

В приложение не включаются generated-файлы, папки `build/`, `dist/`, `instance/`, `logs/`, `uploads/`, реальные содержимые базы SQLite, секретные ключи, приватные загруженные изображения и любые runtime-артефакты. Код тестов следует приводить только как выбранные фрагменты, подтверждающие методику проверки, а не как полный файл.
