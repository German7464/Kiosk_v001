# План тест-кейсов для курсовой работы Kiosk_v001

## Назначение документа

Документ задаёт набор ручных и автоматизированных тест-кейсов для описания тестирования Kiosk_v001 в курсовой работе. Поле «Результат» оставлено как placeholder для заполнения после выполнения проверок.

## TC-001. Вход администратора

- ID: TC-001
- Приоритет: высокий
- Идея: проверить доступ в панель администратора по текущим учётным данным.
- Предусловие: сервер запущен, пользователь `admin` существует.
- Шаги: открыть `/admin/login`; ввести логин `admin`; ввести текущий пароль; отправить форму.
- Ожидаемый результат: пользователь перенаправлен на `/admin`, отображается панель администратора.
- Результат: не заполнено.

## TC-002. Создание события

- ID: TC-002
- Приоритет: высокий
- Идея: проверить создание карточки события.
- Предусловие: администратор вошёл в систему.
- Шаги: открыть `/admin/events/create`; заполнить title, event date, place, short description, full description, status; при необходимости выбрать image; сохранить.
- Ожидаемый результат: событие создано, отображается в `/admin/events`, `content_version` увеличен.
- Результат: не заполнено.

## TC-003. Редактирование события

- ID: TC-003
- Приоритет: высокий
- Идея: проверить изменение данных существующего события.
- Предусловие: существует событие, администратор вошёл в систему.
- Шаги: открыть `/admin/events/<id>/edit`; изменить название, дату, место или описание; сохранить.
- Ожидаемый результат: изменения сохранены, обновлённые данные отображаются в admin panel и API для active события.
- Результат: не заполнено.

## TC-004. Скрытие и показ события

- ID: TC-004
- Приоритет: высокий
- Идея: проверить статус `hidden`/`active`.
- Предусловие: существует событие.
- Шаги: на `/admin/events` переключить статус события; проверить `/api/events`; переключить статус обратно.
- Ожидаемый результат: hidden событие не отображается в `/api/events`, active событие отображается.
- Результат: не заполнено.

## TC-005. Создание тега

- ID: TC-005
- Приоритет: средний
- Идея: проверить добавление нового тега.
- Предусловие: администратор вошёл в систему.

- Ожидаемый результат: тег появляется в списке, доступен для назначения событиям.
- Результат: не заполнено.

## TC-006. Назначение тега событию

- ID: TC-006
- Приоритет: высокий

- Предусловие: существует событие и тег.

- Ожидаемый результат: в API у события присутствует назначенный тег.
- Результат: не заполнено.

## TC-009. Отображение главного экрана киоска

- Предусловие: сервер запущен.
- Шаги: открыть `/kiosk`.
- Ожидаемый результат: отображается главный экран киоска с системным названием, текстами, кнопкой событий и fullscreen button.
- Результат: не заполнено.

## TC-010. Отображение событий на киоске

- ID: TC-010
- Приоритет: высокий
- Идея: проверить `/kiosk/events`.
- Предусловие: существует хотя бы одно active событие.
- Шаги: открыть `/kiosk/events`.
- Ожидаемый результат: отображается карточка active события, работают previous/next controls и empty state при отсутствии active событий.
- Результат: не заполнено.

## TC-011. Фильтрация тегов на `/kiosk/events`

- ID: TC-011
- Приоритет: средний
- Идея: проверить фильтрацию active событий по назначенным тегам.
- Предусловие: есть active события с разными тегами.
- Шаги: открыть `/kiosk/events`; нажать tag button; открыть modal all tags и выбрать тег; нажать all events.
- Ожидаемый результат: выбранный тег показывает только связанные события, all events возвращает полный active список.
- Результат: не заполнено.

## TC-012. TV display mode

## TC-013. `/api/version` auto-update behavior

- ID: TC-013
- Приоритет: высокий
- Идея: проверить механизм обновления клиентских экранов.
- Предусловие: клиентский экран открыт, администратор вошёл в систему.
- Шаги: запросить `/api/version`; изменить событие или настройки; повторно запросить `/api/version`.
- Ожидаемый результат: значение `content_version` увеличивается; клиентский JS обнаруживает изменение и применяет обновление после случайной задержки.
- Результат: не заполнено.

## TC-014. Защищённый выход из fullscreen на `/kiosk`

- ID: TC-014
- Приоритет: высокий
- Идея: проверить, что публичная кнопка не выходит из fullscreen без admin credentials.
- Предусловие: `/kiosk` открыт, fullscreen активирован.
- Шаги: нажать fullscreen button повторно; ввести неверные credentials; затем ввести текущие admin credentials.
- Ожидаемый результат: при неверных данных fullscreen остаётся активным; при верных данных разрешается выход.
- Результат: не заполнено.

## TC-015. LAN startup

- ID: TC-015
- Приоритет: высокий
- Идея: проверить доступность сервера в локальной сети.
- Предусловие: устройства в одной Wi-Fi/LAN сети, firewall разрешает порт.
- Шаги: запустить `python serve.py`; открыть `http://127.0.0.1:5000/tv` на сервере; открыть `http://<computer-lan-ip>:5000/tv` на смартфоне или Smart TV.
- Ожидаемый результат: сервер доступен локально и по LAN IP.
- Результат: не заполнено.

## TC-016. EXE startup

- ID: TC-016
- Приоритет: высокий
- Идея: проверить packaged startup.
- Предусловие: EXE собран через PyInstaller.
- Шаги: запустить `dist/Kiosk_v001/Kiosk_v001.exe`; проверить вывод URL; открыть public routes.
- Ожидаемый результат: EXE запускает Waitress, bind по умолчанию `0.0.0.0`, runtime data создаётся рядом с EXE.
- Результат: не заполнено.

## TC-017. CLI reset admin password

- ID: TC-017
- Приоритет: высокий
- Идея: проверить локальный сброс пароля администратора.
- Предусловие: сервер остановлен или используется тестовая БД.
- Шаги: выполнить `python serve.py --reset-admin-password`; сохранить временный пароль; войти как admin; сменить пароль.
- Ожидаемый результат: временный пароль выводится один раз, в БД хранится только hash, web reset route отсутствует.
- Результат: не заполнено.

## Автоматизированные проверки

Для курсовой работы отдельно указать, что часть регрессионных проверок реализована в `tests/test_mvp_smoke.py`. Они используют временную SQLite database и temporary upload folders, не затрагивают реальный `instance/kiosk.sqlite`, проверяют маршруты, admin authentication, API visibility, settings/content version, image/icon processing, startup helpers, runtime secret handling и fullscreen unlock validation.
