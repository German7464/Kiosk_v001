# Черновик курсовой работы. Заключение и список литературы

## Заключение

В ходе выполнения курсового проекта была достигнута поставленная цель: спроектирована и разработана локальная клиент-серверная информационная система для управления карточками событий и их отображения на информационном киоске, Smart TV и экране предпросмотра. Разработанный программный продукт Kiosk_v001 ориентирован на эксплуатацию в локальной сети и позволяет централизованно управлять информацией без обязательного размещения системы в облаке или публикации в интернете.

На этапе предпроектного исследования была проанализирована предметная область отображения событий на публичных экранах. Были рассмотрены основные участники системы: администратор, посетитель киоска, зритель TV-экрана и локальный оператор. По результатам анализа были сформулированы функциональные и нефункциональные требования к программе. К функциональным требованиям отнесены авторизация администратора, управление событиями и тегами, загрузка изображений, настройка системных параметров, отображение публичных экранов, работа API и механизм обновления клиентских страниц. Нефункциональные требования включают локальную эксплуатацию, доступность в LAN, хранение данных в SQLite, сохранение runtime-данных вне исполняемых файлов, читаемость интерфейса на публичных экранах и базовую безопасность административных сессий.

В рамках проектирования была выбрана модульная монолитная архитектура на базе Python и Flask. Такое решение соответствует масштабу проекта: приложение разворачивается как единая локальная система, но его логика разделена на модули конфигурации, базы данных, административной панели, публичного API, обработки изображений, интернационализации и серверного запуска. Для хранения данных была организована локальная SQLite-база, содержащая пользователей, события, теги, связи между событиями и тегами, системные настройки и версии содержимого. Runtime-данные, включая `instance/kiosk.sqlite`, `instance/secret_key.txt` и загруженные файлы, размещаются вне собранного приложения, что упрощает эксплуатацию и сохранение данных при обновлении программы.

В практической части была реализована административная панель, через которую администратор может входить в систему, создавать и редактировать события, скрывать и показывать карточки, назначать теги, загружать изображения, изменять системные настройки и менять пароль. Для публичного отображения реализованы страницы `/kiosk`, `/kiosk/events`, `/tv` и `/preview`. Стартовая страница киоска показывает настраиваемые тексты и переход к событиям, страница событий поддерживает просмотр карточек и фильтрацию по тегам, TV-режим автоматически демонстрирует активные события, а экран предпросмотра помогает проверять основные режимы отображения.

Для обмена данными между сервером и клиентскими экранами был реализован публичный read-only API. Endpoint `/api/version` используется клиентами для проверки изменений содержимого. При изменении событий, тегов, настроек, изображений или иконки значение `content_version` увеличивается, после чего открытые экраны могут обновиться. Для уменьшения одновременной нагрузки предусмотрена случайная задержка перед применением обновления. Также реализована загрузка и оптимизация изображений с помощью Pillow: исходные файлы сохраняются отдельно, а для публичных экранов создаются оптимизированные версии для киоска, TV и миниатюр.

Для эксплуатации системы подготовлен production-style запуск через Waitress и CLI-скрипт `serve.py`. Производственный запуск по умолчанию доступен в локальной сети через host `0.0.0.0`, при этом локальный режим может быть выбран явно через `--host 127.0.0.1`. Для распространения на Windows подготовлена сборка через PyInstaller по спецификации `Kiosk_v001.spec`. EXE-режим упрощает запуск системы для оператора, поддерживает внешние runtime-данные, автоматический поиск опционального `ClientKiosk.exe`, fallback-открытие страницы в браузере, режим `--no-client` и CLI-сброс пароля администратора.

Практическая значимость разработанной системы заключается в том, что события управляются централизованно с одного локального сервера, а публичные экраны получают актуальные данные через браузер или внешний клиент в пределах локальной сети. Такой подход подходит для небольших учреждений, учебных площадок, офисов и локальных мероприятий, где не требуется обязательная облачная инфраструктура. EXE-сборка дополнительно упрощает эксплуатацию на Windows-компьютере, поскольку оператор может запускать систему как обычное приложение.

Для проверки работоспособности были подготовлены regression smoke tests. Автоматизированные тесты используют временную базу данных и временные каталоги загрузок, не затрагивают рабочий файл `instance/kiosk.sqlite` и проверяют ключевые сценарии: доступность маршрутов, авторизацию администратора, видимость активных и скрытых событий в API, работу тегов, сохранение настроек, увеличение версии содержимого, обработку изображений и иконки, защищённый выход из полноэкранного режима, стартовые helpers и постоянный runtime-секрет. Дополнительно подготовлены планы тест-кейсов, диаграмм, приложений и источников для дальнейшего оформления курсовой работы.

Таким образом, в результате курсового проекта была получена работоспособная локальная информационная система, соответствующая заявленным требованиям MVP и дополненная практическими улучшениями для эксплуатации. Возможные направления дальнейшего развития могут включать более развитый механизм резервного копирования, расширенные роли пользователей, более подробную эксплуатационную документацию для разных сценариев установки и дополнительные режимы отображения. Эти направления являются необязательными для завершённого MVP и могут рассматриваться как будущие улучшения.
