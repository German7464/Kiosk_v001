# План курсовой работы по проекту Kiosk_v001

## Назначение документа

Документ задаёт структуру курсовой работы по дисциплине «Проектирование информационных систем» для проекта Kiosk_v001. Материал должен описывать уже реализованную локальную клиент-серверную систему для отображения карточек событий на киоске, Smart TV, экране предпросмотра и в панели администратора.

## Титульный лист

Указать образовательную организацию, дисциплину, тему курсовой работы, автора, группу, руководителя, город и год. Тему можно сформулировать как «Проектирование информационной системы локального киоска событий Kiosk_v001».

## Содержание

Сформировать после финального набора разделов, подразделов, списка литературы и приложений. В содержании должны быть отражены введение, три главы, заключение, список литературы и приложения.

## Введение

Описать актуальность локальных информационных систем для отображения событий на публичных экранах. Показать проблему: администратору нужно быстро публиковать события, а посетителям и зрителям нужно видеть актуальную информацию на киоске и TV без облачной инфраструктуры. Указать объект исследования, предмет исследования, цель, задачи, методы проектирования, практическую значимость и краткую характеристику разработанного приложения.

## 1 Постановка задачи

Раздел должен определить, какую практическую задачу решает Kiosk_v001, какие ограничения приняты и почему система реализована как локальное клиент-серверное приложение.

### 1.1 Обоснование необходимости разработки

Описать потребность в локальном информационном киоске для учреждения, офиса, учебной организации или площадки мероприятий. Обосновать отказ от облачных сервисов для MVP: простое развёртывание, работа в локальной сети, контроль данных, отсутствие необходимости в отдельном интернет-публишере.

### 1.2 Техническое описание задачи

Перечислить основные режимы: `/kiosk`, `/kiosk/events`, `/tv`, `/preview`, `/admin`. Описать роли системы: администратор управляет событиями, тегами, изображениями и настройками; публичные клиенты отображают активные события; API отдаёт данные для экранов; `serve.py` запускает сервер в LAN-режиме.

### 1.3 Анализ предметной области

Описать предметную область «информационная система событий»: событие, дата, место, краткое и полное описание, статус показа, теги, изображения, системные настройки. Отдельно отметить сценарии публичного отображения: интерактивный киоск, пассивный TV-экран, экран предпросмотра.

### 1.4 Требования к программе

Разделить требования на функциональные и нефункциональные. Функциональные: CRUD событий, управление тегами, загрузка изображений, настройки, API, автообновление клиентов, fullscreen-поведение, EXE-запуск. Нефункциональные: локальная работа, простая эксплуатация, SQLite, хранение runtime-данных вне EXE, адаптивный интерфейс, безопасность админ-сессии через runtime `SECRET_KEY`.

### 1.5 Обоснование проектных решений

Обосновать выбор Flask, SQLite, HTML/CSS/JavaScript, Pillow, Waitress и PyInstaller. Пояснить модульную монолитную архитектуру: один локальный сервер, отдельные feature-модули admin и API, шаблоны и статические файлы, внешний runtime-каталог.

### 1.6 Обзор и анализ существующих решений

Сравнить с ручным размещением объявлений, презентациями, облачными digital signage сервисами и CMS. Отметить, что Kiosk_v001 покрывает локальный сценарий без сложной инфраструктуры и без функций, не входящих в MVP: статистики, облака, мобильного приложения, новостной ленты.

### 1.7 Выводы предпроектного исследования

Сформулировать вывод: требуется локальная информационная система с админ-панелью, публичными экранами, API обновлений, обработкой изображений, упаковкой в EXE и возможностью работы в LAN.

## 2 Теоретическая часть

Раздел должен дать теоретическую основу, на которой построено проектирование Kiosk_v001.

### 2.1 Локальные клиент-серверные информационные системы

Описать модель клиент-серверного взаимодействия в локальной сети: сервер на Windows-компьютере, браузерные клиенты, HTTP-маршруты, JSON API, SQLite как локальное хранилище.

### 2.2 Информационные киоски и Smart TV как средства отображения информации

Описать особенности публичных экранов: читаемость с расстояния, понятная навигация, устойчивое отображение при отсутствии активных данных, fullscreen-режим, простое восстановление после обновления контента.

### 2.3 Проектирование пользовательских интерфейсов для публичных экранов

Рассмотреть требования к интерфейсам киоска и TV: крупные элементы, краткие тексты, визуальное разделение изображения и описания, индикация пустого состояния, предупреждение о возврате на главный экран при бездействии.

### 2.4 Средства моделирования информационных систем

Кратко описать применяемые нотации: IDEF0 по Р 50.1.028-2001, UML 2.5.1 для Use Case, Sequence и ER-представления, C4 Model для архитектуры, блок-схемы по ГОСТ 19.701-90 / ISO 5807-85.

## 3 Практическая часть

Раздел должен описывать проектирование и реализацию Kiosk_v001 на основе фактического кода.

### 3.1 Анализ задачи

Определить акторов: администратор, посетитель киоска, зритель TV-экрана, локальный оператор. Описать основные сценарии: создание события, показ события, фильтрация по тегу, обновление клиентов, запуск EXE.

### 3.2 Описание логической структуры системы

Описать основные подсистемы: администрирование, публичный API, экраны отображения, обработка изображений, хранилище данных, запуск и упаковка. Указать связи между таблицами `events`, `tags`, `event_tags`, `settings`, `content_versions`, `users`.

### 3.3 Архитектура программного решения

Описать application factory, Flask blueprints, `kiosk/features/admin`, `kiosk/features/api`, шаблоны, статические JS/CSS, переводы ru/en/de, Waitress-стартер, PyInstaller-упаковку и внешний runtime-каталог.

### 3.4 Разработка программных модулей

Описать модули: `kiosk/app.py`, `kiosk/config.py`, `kiosk/database.py`, `kiosk/server.py`, `kiosk/core/images.py`, `kiosk/core/i18n.py`, admin routes, API routes, JS для kiosk home, kiosk events, TV и admin preview.

### 3.5 Организация хранения данных

Описать SQLite, путь `instance/kiosk.sqlite`, таблицы пользователей, событий, тегов, связей, настроек и версий контента. Отдельно описать хранение приватных оригиналов изображений и публичных оптимизированных файлов.

### 3.6 Реализация пользовательского интерфейса

Описать экраны `/kiosk`, `/kiosk/events`, `/tv`, `/preview`, `/admin/login`, `/admin`, `/admin/events`, `/admin/events/create`, `/admin/tags`, `/admin/settings`, `/admin/password/change`. Указать, что интерфейс использует серверные шаблоны Jinja, общий CSS и отдельные JS-файлы.

### 3.7 Реализация обновления клиентских экранов

Описать `/api/version`, content version, периодический polling, случайную задержку 0-10 секунд, обновление `/kiosk`, `/kiosk/events`, `/tv` и `/preview`. Отдельно описать таймер бездействия `/kiosk/events`.

### 3.8 Сборка исполняемого файла

Описать `Kiosk_v001.spec`, PyInstaller, включение templates/static/translations, внешний runtime beside EXE, LAN-startup по умолчанию, `ClientKiosk.exe` как внешний optional launcher, browser fallback и `--no-client`.

### 3.9 Тестирование программного продукта

Описать автоматизированные smoke tests из `tests/test_mvp_smoke.py` и ручные тест-кейсы. Указать временную БД и временные upload-папки в тестах. Перечислить проверяемые области: маршруты, auth, API, изображения, настройки, fullscreen unlock, startup helpers.

### 3.10 Эксплуатационная документация

Описать запуск `python run.py`, `python serve.py`, `python serve.py --host 127.0.0.1`, `python serve.py --no-client`, `python serve.py --reset-admin-password`, запуск EXE, подключение со смартфона/Smart TV по LAN IP и базовые рекомендации по Windows Firewall/VPN/Wi-Fi.
