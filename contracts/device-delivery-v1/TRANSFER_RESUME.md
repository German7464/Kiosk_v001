# Events delivery: interrupted and incremental capture

Additive transfer profile, 2026-11-04. The [frozen laboratory protocol](README.md) still governs trust, enrollment, assignments, admission and actual-ready receipts. This profile changes artifact transport only; it introduces no authority, credential, renderer, store or time source. PC1 server support is implemented; matching Android support requires the coordinated task in [the task record](../../docs/ANDROID_TASK_DRAFT.md). Factual acceptance remains in the sole ledger.

## HTTP behavior

An authorized current-assignment artifact GET returns a strong `ETag: "<inventory sha256>"`, `Accept-Ranges: bytes`, exact `Content-Length`, octet-stream and `Cache-Control: no-store, no-transform`. ETag is a byte validator, not authority. Authentication, inventory membership, current assignment and whole-file size/SHA256 verification precede every response, including partial responses.

To resume, send `Range: bytes=<start>-` or `bytes=<start>-<end>` AND `If-Range: "<inventory sha256>"`. Only decimal nonnegative offsets of at most 20 digits are accepted. A matching validator yields 206 with exact `Content-Range: bytes start-end/total`; an end beyond EOF is clamped. Invalid, suffix, multiple, reversed or unsatisfiable ranges with a matching validator yield empty 416 and `Content-Range: bytes */total`. No range, absent validator, weak validator or mismatching validator returns FULL 200; clients must replace staging, never append that response. This intentionally supports only a strict single-range subset.

Existing 401/403/404/409/429/503 semantics apply. Assignment changes return 409, not bytes from an arbitrary retained package. There is no unauthenticated content-hash endpoint. No conditional 304 or compressed artifact representation is used. A client rejects unexpected encoding, response status, validator, length, Content-Range or trailing bytes. Complete assembled bytes MUST match inventory SHA256 before capture/admission. A valid suffix alone never authenticates the old local prefix.

## Native durable capture

Keep one synchronization owner and one incomplete candidate under existing private storage/budgets. Persist the exact authenticated assignment identity, file identity (group/path/size/hash), and actual durable prefix length. After interruption/fresh process, revalidate native enrollment/authority/current assignment before continuing NEW admission; uncertain-boot time still follows the existing explicit confirmation rule. A lost assignment or changed manifest cannot authorize stale staging. Reconcile metadata against actual staging length after a crash; reject impossible offsets and unowned paths. Bound total temporary bytes/files using the existing capture limits, include prefixes and reused copies in accounting, preserve current/recovery publications and never evict them for space.

Reuse a complete locally owned file only when its actual size and SHA256 match the NEW authorized inventory. Copy it into owned capture without mutating the source or following arbitrary links. Reuse may span package/kiosk/tv identities only through exact bytes and supported path semantics. Inventory hashes select bytes; they cannot authorize a candidate or replace full package/image/preparation checks. Download only missing or changed bytes; unchanged complete assignments continue to avoid any artifact GET. Provide explicit full-resync fallback that discards only owned incomplete capture and still passes the same authority/admission gates.

On valid 206, check all response bounds before append, write durably within budget, and verify the completed file. On 200 after a resume request, restart that file from zero. On 416, reconcile/refetch assignment and restart only the affected owned staging file with bounded retries; never spin. On 409, refetch assignment and abandon only incompatible owned candidate work. On 401 stop new content requests and retain current offline display. A full-file mismatch restarts only bounded work and must not activate or emit ready.

## Load and scope

The single-process laboratory server admits at most two artifact responses across all devices, including full-file preverification, and returns 429 `transfer_busy` / `Retry-After: 5` instead of building an artifact queue. Each stream is paced to 2 MiB/s with 64 KiB chunks, bounding payload to 4 MiB/s aggregate per process. This is application pacing, not a measured NIC/fleet guarantee. Close/error/disconnect releases its slot. Metadata/enrollment/receipt routes do not acquire artifact slots; the existing four-worker lab setup retains capacity for them. Proxy and operating-system queues still exist; no full production-load acceptance is claimed.

Native retains one network/capture cycle and existing bounded backoff, honors Retry-After with a bounded delay, and does not fork concurrent download attempts. Expose diagnostic counts for reused complete bytes, new received bytes, resumed offset, full restart reason, candidate identity and current visible identity; never label bytes received as actual-ready. Existing actual-ready receipts remain unchanged. The wider operator state/target-set UI, discovery/device profiles, authority rotation/recovery and unattended trusted time remain separate mandatory stage5 work.
