# Kiosk native device delivery v1 — laboratory profile

Owner selected direct isolated integration on 2026-11-04, with real source verification retained. This contract freezes the first server/Android pilot, not full stage5 acceptance. Existing [Events-v1](../events-v1/README.md) stays unchanged. [Current evidence](../../docs/TZ_PROGRESS.md) is authoritative for results. One server, one phone, complete artifact transfer; no discovery, incremental/resume, rotation/failover, release or fleet claims.

## Encoding and bounds

All JSON is UTF-8 without BOM, duplicate keys, lone surrogates, trailing input, NaN or floating-point/exponent numbers. Integer tokens fit signed64; individual counters/timestamps/sizes must be nonnegative and exclude boolean. Fields listed below are exact unless stated otherwise. JSON field ordering/whitespace are irrelevant EXCEPT original signed payload bytes. Metadata response/request cap 2MiB; trust envelope cap 16KiB, decoded trust payload cap 8KiB, RSA SPKI cap 1KiB; RSA signature exactly384 bytes. Standard padded canonical Base64 only. IDs: ASCII letters/digits/underscore/dot/hyphen,1–128 characters. Client-generated request_id,nonce,device_id and receipt_id use independent random UUIDs or128-bit-or-greater random IDs. Secrets/device_code are32 random bytes, lowercase hex64; the native secret is never a URL parameter or diagnostic field. SHA256 is lowercase hex64. All publication paths use existing Events portable-path rules; inventory duplicates/casefold aliases are refused.

## Bootstrap, TLS and trust

The operator copies bootstrap JSON from the authenticated administrative surface (or the independently delivered public lab file) into a native confirmation screen. Exact fields: version=1,bootstrap_id,group_id,server_id,origin,tls_ca_pem,group_key_id,group_spki_base64,issued_at,expires_at. Times are integer UTC seconds. `group_key_id` is SHA256 of the decoded group SPKI DER. Pin the independently confirmed key BEFORE parsing any signed envelope. Origin is exact `https://host:explicit-port`, with no userinfo/path/query/fragment. No group membership follows from bootstrap alone.

Native HTTPS validates chain to the bootstrap CA AND hostname/IP SAN; no trust-all manager, hostname bypass, system root installation or HTTP fallback. Reject all redirects. WebView has no network/native-secret bridge. Android INTERNET permission is authorized for this native transport block. CA/group private keys stay in PC1's separate admin-private fixture directory; only TLS private key resides with the isolated server. Reference for fixture certificate issuance: [Microsoft CertificateRequest](https://learn.microsoft.com/dotnet/api/System.Security.Cryptography.X509Certificates.CertificateRequest.Create).

Signed envelope exact fields: version=1,key_id,algorithm=`RSA3072-SHA256-PKCS1-v1_5`,payload_base64,signature_base64. Input to signature: ASCII `Kiosk/GroupTrust/v1`, one NUL byte, original decoded payload bytes. RSA modulus3072/exponent65537, SHA256/PKCS1-v1_5. Envelope key_id must match the independent bootstrap; no envelope-supplied key is trusted. This is a new domain/schema, not synthetic v0.

Payload exact fields: version=1,group_id,generation,issued_at,expires_at,servers. Generation positive. Exactly one server: server_id,origin,tls_spki_sha256,roles=["publisher"]. Bind group/server/origin and certificate SPKI observed by native TLS; chain/name verification remains mandatory. Require issued_at<=now<expires_at and issued_at<expires_at. Higher generation is durably persisted before new admission; equal generation requires identical original payload; lower refuses. Persist the anchor, exact accepted bytes/digest/generation and highest accepted time. Uncertain reboot clock/backward clock/expiry blocks NEW authority/admission, preserving accepted offline display. Monotonic elapsed time prevents in-process backward extension. No unsigned HTTP Date authority. Explicit re-enrollment handles unrecoverable authority loss; no automatic key replacement.

## Enrollment

POST `/api/v2/device/authorize`, JSON exact fields: version=1,request_id,device_id,group_id,profile,origin,nonce,secret_verifier. Profile=`events-phone-lab-v1`. Client generates and durably stores native secret BEFORE transmitting `secret_verifier=SHA256(raw32 secret bytes)`. The verifier alone cannot authenticate subsequent content requests.

200 response exact fields: version=1,request_id,device_code,user_code,expires_in,interval. TTL600s,interval5s,user_code8 unambiguous characters. Same request_id+identical binding retries return SAME request/code while live; changed binding409; expired410. Pending cap128; native device cap16. Pending secrets remain confined to isolated server DB and native private state.

GET `/admin/devices/pending`: existing admin session required. JSON version=1,requests; each request has request_id,binding,user_code,expires_at,state,binding_sha256. `binding` omits secret_verifier for admin display; binding_sha256 was computed from the ORIGINAL complete binding using sorted compact JSON with UTF-8 non-ASCII, and must be echoed verbatim. Compare shown device/group/profile/origin/nonce and human code. POST `/admin/devices/{request_id}/decision` with existing admin session+X-CSRF-Token and JSON exact user_code,binding_sha256,decision=(approve|deny). Atomic repeated approve yields the SAME credential_id. Another approved enrollment for the same device atomically replaces its old credential. No display credential authorizes admin routes.

POST `/api/v2/device/token`, JSON {device_code}. Pending202 with version=1,state=pending,interval; polling too fast429. Approved200 fields: version=1,state=approved,device_id,profile,credential_id,expires_at,scopes=["read_assignment","submit_receipt"]. Retrying a lost response does not mint a new credential. Denied403; expired410. Credential finite TTL7days, renewal by explicit re-enrollment; no refresh-token claim. `Authorization: Bearer <native secret hex64>` authenticates all subsequent native operations. `GET /api/v2/client/status` recovers the same approved public credential metadata after enrollment-request expiry. POST `/admin/devices/{device_id}/revoke`, JSON {}, admin+CSRF, revokes immediately; accepted offline content remains usable.

## Assignment and complete artifacts

GET `/api/v2/group/trust`: authenticated, returns signed envelope. Verify it before content admission.

GET `/api/v2/client/assignment?renderer={client_build_id}&resource_profile=events-phone-lab-v1`: authenticated; renderer/profile mismatch409 requires_update. 200 exact fields: version=1,group_id,device_id,profile,generation,metadata_sha256,publication. Generation is assignment counter, distinct from content revision and authority generation. Scope every request/response to bootstrap identity and approved device. Assignment metadata is attested by the authorized TLS publisher; hashes alone are not source authority or an independent proof of HTML derivation.

`publication` exact fields: version=1,package_id,revision,raw_manifest_sha256,renderer,resource_profile,limits,windows_images,package,kiosk,tv. `metadata_sha256` hashes publication object encoded as sorted compact JSON/UTF-8 non-ASCII. Preserve exact authenticated delivery.json bytes or implement that encoding precisely before reusing this hash; it is not SHA256 of arbitrary response whitespace. `package_id` is existing canonical manifest identity, distinct from raw manifest hash.

Renderer exact fields: build_id,js_sha256,css_sha256. Native client accepts its independently supported JS/CSS/build pins; content cannot install new executable code. Each of package/kiosk/tv has exact `files` array of {path,size,sha256}, including manifest.json/view.json respectively. File lists are exact complete inventories. Windows preparation uses the existing full verifier and both-mode renderer; windows_images maps every referenced image plus resources/static/img/site_icon.png to {sha256,result="VERIFIED"}. Native admission still checks exact captured bytes and Android image capability.

Resource limits (experimental phone pilot, no universal hard RSS/decode deadline guarantee): max_pixels2000000,max_live_bytes33554432,per_image_ms5000,total_image_ms15000,capture_bytes201326592,capture_files30003,min_free_bytes16777216. They map to existing PreparedAdmission.ImageBudget and CapturedCandidate.Budget. Static single-frame PNG/JPEG only; unsupported media/profile refuses a NEW candidate, preserving prior display. These explicit lab settings do not change global product media obligations. Server publication cap192MiB and retained catalog cap512MiB; no deletion of active/recovery files to make space.

GET `/api/v2/publications/{package_id}/{package|kiosk|tv}/{portable_relative_path}`: authenticated; only current assigned package/group inventory files, octet-stream, exact Content-Length. Capture under existing app-private ownership/budgets; reject short/long/hash-mismatched bytes and unsupported paths. If assignment changes during download,409; discard only owned staging and refetch assignment, leaving current display intact. No archive extraction/importer/resumable claim. No DB, original/private image, credential or unlisted template is downloadable.

Use existing CapturedCandidate/PreparedAdmission/FixturePublicationStore/coordinator for admission. Metadata maps to existing typed witnesses; names containing DevelopmentWitness are historical data carriers and do not confer development authority. `preparationReference` can be metadata_sha256. Native SourceVerifier NEW_ACTIVATION must independently validate live bootstrap/TLS/signed authority, exact assignment and request facts; persist a durable authorization association only after validation. PRIVATE_REOPEN validates an existing accepted association and exact request facts, allowing offline display without new online authority or test issuer. An untrusted persisted self-assertion cannot create that association. Source trust state and accepted display evidence must survive fresh ordinary startup; no caller boolean/test class/catalog allowlist.

## Ready receipts and failures

POST `/api/v2/client/receipts`, authenticated JSON exact fields: version=1,receipt_id,group_id,device_id,generation,package_id,mode=(kiosk|tv),session,result=ready. Generate and durably queue receipt_id only AFTER actual mode/session ready. Retry SAME body/id after reconnect; uniqueness(device_id,receipt_id), duplicate200, same ID/different body409. Historical queued receipts require an exact retained profile/generation/package assignment. A receipt is a native readiness report, not proof of physical screen power or human observation. Keep pointer, visible identity and last-ready separate; renderer failure after pointer commit is not automatic rollback.

Errors: JSON version=1,error=stable_code. 400 invalid JSON/fields/types;401 invalid/expired/revoked native credential;403 wrong binding/denied/plain HTTP;404 missing authorized assignment/file;409 request/receipt conflict, changed assignment or unsupported capability;410 expired enrollment;413 body/publication cap;415 JSON required;429 capacity/rate/poll delay;503 unavailable/corrupt publication;507 catalog full. Admin unauthenticated GET redirects302 to existing login, and existing CSRF403 response remains HTML. No paths/secrets in API errors. Native rate limit1200 requests/endpoint/source/min,2400/source/min; bounded limiter capacity2048 entries. These are lab configuration, not fleet measurements.
